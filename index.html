While I sleep, sixteen agents ship my game.

I build Dungeon Heroes, a commercial Unity game, and I wanted it to keep being built after I stopped for the day. So I built a fleet: sixteen agents that run overnight against the production repository. I did not guess at how to divide the work between them. I ran a co-change analysis over the repository's history to learn which files actually move together, gave the Unity scenes one serial lane, and spread everything else across four parallel worktrees. The agents never collide.

I made every agent report back in the same fixed contract: branch, files touched, what to verify, a confidence level, and anything it noticed outside its scope. Those findings become the next night's issues, so the fleet feeds itself work. I run the checks cheapest first, and I kept exactly one human gate, because what a screen looks like on a real device is information no pipeline holds.

Agents turn model spend into an operating cost, so I measured it like one and bent the curve: I drove the expensive high-context share of the bill from 42.0% down to 12.1%, clearing the 20% bar with room to spare. And when I auditioned local models for the cheap end of the routing, I wrote them an eval with a hard 0.95 accuracy bar first. They scored 77.5% and 85.0%. I did not give them the job.

The best delete of my career.

-162,256 lines, removed in one commit

Before the fleet, I built a 35,000-line pipeline that turned written briefs into working Unity screens through typed contracts and five human gates. It shipped real screens into the game, and I made it price its own work: $67 to $98 per accepted screen, with every rerun billed to whatever caused it.

Then I read the ledger it kept, and the ledger was blunt: the expensive validator half had zero confirmed true positives across 730 findings while carrying about half the spend. So I deleted it, 1,240 files in one commit, and moved verification onto ground truth: the compiler, the filesystem, the live scene. I built the fleet in its place, and it ships more with a fraction of the machinery. Anyone can build a system. The job is reading the ledger honestly enough to unbuild one.

Stepland · Godot · one of three core programmers · live on both stores

The whole game runs on one number. It was failing.

I was one of three core programmers on Stepland, a game that turns real-world walking into a Tamagotchi-style pet. Every currency, streak, and reward sits downstream of one number: the steps the player took. And that number arrived through a third-party health hub that could report connected while delivering zero, which to a player is the game being broken at first launch.

I proposed cutting the dependency and reading the Android pedometer directly. Then I built the replacement in a week, in Kotlin, a language I had never written: the sensor reader, the background worker that keeps steps accruing with the app closed, the bridge from Godot to Android. One permission prompt, no second-app setup, no silent zeroes. It has been stable ever since.

I brought the same speed to deadlines. I rebuilt the tutorial as 82 declarative, resumable steps and landed it on the opening day of the 4YFN showcase, driving coding-agent sessions inside the production repository. And before a screen got drawn, I blocked it out and the artist dressed it. The shipped game keeps my skeletons.

Dungeon Heroes · Unity · C# · solo

A full free-to-play game, built by one person.

The fight is what players see. What decides survival is everything they never notice, the systems solo projects usually skip, and I built every one of them. I resolve damage through an ordered stage pipeline, which is how 174 spells can reach into the same hit while the catalogue keeps growing. I tune the combat in tenths of a second, and every timing in it is an authored constant with a name.

I put chest odds in tables a designer could write, with a pity floor you can reason about. I version and migrate save files, never overwrite them, and I made sure a migration that runs twice cannot pay its rewards twice. My favourite decision: the balance analyzer refuses runs recorded on my own dev machine, because the developer is the least representative player there is. I built the game not to trust me.

I carried it to signed Android release builds with the store compliance done, and I build it at fleet speed: the sixteen agents above write into this repository every night.

Purple Pwny · C# · Unity · 2023 to 2024

I gave the game a player. In 2024.

A roguelike's balance question is how an item performs in the hands of someone good, and no human plays ten thousand dungeons. So I wrote DunAI: 552 lines, delivered in one commit, a hand-authored decision agent that plays the dungeon crawler competently. From that commit on, balance was measured against skilled play instead of random rolls. I built it as rules, not a learned policy, on purpose: when a number comes out strange, you read the file and see exactly why.

On the same job I shipped the Seashore biome, its boss, and about twenty relics I designed from nothing but a name and an icon, plus a betting game whose race I compute backwards from a predetermined winner and which still plays as a race. It is all playable in the browser.

I taught myself everything on this page.

I left school at seventeen and learned to program on my own: C# first, then Unity, then game design from books, courses, and whatever I was building at the time. Over the next six years I built more than fifteen prototypes, each in a different genre. I would start a project, drive it to a working prototype, then deliberately stop and start again somewhere new. That was my curriculum: every kind of system on this page, I had already built in miniature before anyone paid me to build one for real.

Three years ago the prototypes became a profession. The rest is above: a team credit live on both app stores, a commercial free-to-play game of my own, and a fleet of agents that ships it while I sleep.
